Дата исследования: 2026-10-27 · источники: neoforged.net (релизная лента),
docs.neoforged.net (версионированные ветки), релизный пост 21.9.

## Решение для v3

1. **1.21.1 и 1.20.1 — обязательные профили** (исходная задача миграции) —
   оба полностью поддержаны v3 (366 задач neoforge-1.21.1, 35 задач
   forge-1.20.1 в новом наборе + 130 baseline).
2. **Современный профиль (1.21.9+/26.x) — НЕ создан как исполняемый.** Причины:
   - В аудит-среде нет даже 8 ГБ RAM — профиль не был бы верифицируем
     (требование ЭТАПА 9 п.3: профиль только после реальной воспроизводимости).
   - Миграция рендер-модели (render state, SubmitNodeCollector) означает, что
     эталоны НЕ переносятся копированием между 1.21.1 и 1.21.9+ (ТЗ п.5):
     каждая задача современного профиля требует нового эталона с новым API —
     при отсутствии исполнимой среды это дало бы неподтверждённый контент.
3. **Подготовлен каркас**: `data/schema.json` допускает любые
   `target_loader/target_version/environment_id`; в `execution_stages` уже
   есть `dedicated_server_smoke`/`client_smoke`; при появлении >=16 ГБ среды
   современный профиль добавляется генераторами с собственным
   `source_of_truth` (релизные артефакты 21.9+/26.x) и javac-21 self-check.
4. **Отчёты ведутся раздельно по профилям**: `forge-1.20.1`, `neoforge-1.21.1`,
   (будущий) `modern`. Текущий датасет не смешивает профили в сплитах по
   task_family.

## Категории модов (исследование спроса)

По документации NeoForge (разделы docs) и релизным заметкам, категории
с подтверждённым интересом и официальной поддержкой API: GUI/config screens,
рендер (BER/ER — дважды переработаны за год), datagen/ресурсы, networking
(payload API), интеграции (Transfer APIs). v3 закрывает все пять категорий
группами B, C, D, F и A; worldgen и mixins — E и G. Не покрыто (нет
группы): многопользовательские сюжетные системы и сторонние интеграции
(JEI/курейские хуки остаются OPTIONAL_ROOTS-семантикой).
